## 数据和身份规则

- 获奖者仅关联站内用户。原始姓名保留在获奖关联行；用户表保存曾用名、在校日期覆盖值和资料版本。不再要求先创建独立荣誉身份。成员管理与荣誉管理的“用户资料”可维护同一份资料。
- 默认入学日为用户入学年 9 月 1 日，离校日默认加四个日历年；后台可分别覆盖。计入区间为 `[入学日, 离校日)`。未知在校时间不计入；月份/年份精度必须整个日期区间在校，跨边界需进一步核对。
- 审核页按当前姓名、曾用名生成候选；仅唯一符合在校区间的候选会初步预选。重名歧义、日期不全或区间外不预选。候选及预选都不落库，管理员保存审核后才确认用户 ID，已有人工关联优先。
- 公开条件是已核实、用户已关联、符合在校区间且比赛日期不在未来；变更日期或在校时间立即重新计算。团队奖按符合条件的获奖者展示，个人页按用户 ID 筛选。
- 公开接口不返回账号绑定、曾用名、核对备注或候选用户。成员历史接口沿用成员页登录权限。删除用户解除获奖关联，原始姓名及来源保留；未关联者不公开计入。
- 导入按稳定来源编号追加，重复跳过，事件元数据冲突逐行失败并返回原记录；不修改既有审核结果或创建用户，不在采集时自动绑定用户。
- 写操作取得 SQLite 写锁，审核与用户获奖资料更新带版本校验，日期更正校验旧值。旧独立身份表保留；启动迁移仅迁移已有明确账号关联和对应曾用名、在校区间，不按同名猜测。旧独立身份 CRUD/合并预检接口已移除。

## 继续搜集的缺口

1. 天梯赛的正式奖项口径、历史年份和团队/高校奖；不要把全国个人榜的颜色、等级或固定比例当成获奖证明。官方个人榜不支持已测试的 schoolFid/teamFid 筛选，参数会被忽略；使用本校三个队伍的详情接口即可取得名单，避免遍历全榜。全榜探索中遇到 429，已停止该方式，采集脚本改为少量定向读取、每秒一次、HTTP 错误立即停止。
2. 后续优先补充省奖：蓝桥杯广东省赛、天梯赛省级个人/团队/高校奖，以及百度之星和码蹄杯尚缺场次与年份；按届次、赛道、分组和来源分别保留，不将省奖与国奖合并。蓝桥杯第 1–11 届、第 15–17 届也待补采。已保存官网 1–14 届压缩包入口；本轮实际提取仅 12–14 届软件决赛。2024、2026 学校新闻的名单图片需另行校对，不能用新闻发布时间充当比赛日。
3. 百度之星第一场初赛、历史年份和违规/撤销公示与正式名单的最终对照。本轮第二场用的是官网“公示后最终版”，决赛未检出本校。
4. 码蹄杯历史届次和 2026 国赛比赛日。官网同时说明码蹄杯与百度之星人才专项合作，不能将一个赛事奖项自动复制为另一赛事奖项。
5. 各获奖者的真实身份、曾用名、入学日期及特殊学制；没有公开证据时保持待核实。

## 页面与验收说明

沿用现有工作坊的字体、颜色、Button/Input/ActionNotice 和管理双栏。读者先筛赛事/年份，再看获奖者及原始来源；管理员在同一详情核对来源、关联用户、审核。手机只显示列表或详情，详情有“返回列表”。没有新插画或独立视觉系统。

沿用按钮的颜色反馈、列表选中反馈和 ActionNotice 过渡；没有增加长时动画。界面文案保留核对依据和计入条件，没有加入宣传文案。未进行独立子代理评审。

当前后端全量 454 项通过，荣誉和迁移相关 18 项通过；前端 ESLint、Astro check 和生产构建通过。采集 skill 校验通过。

本轮使用独立 `/tmp/sgu-honors-user-preview.db` 验收曾用名保存、候选预选、重名歧义、在校排除、审核公开、刷新和失败保留草稿，以及 390px 无整页溢出。用生产备份的临时副本演练迁移后，97 条奖项和 137 条原始姓名保留，完整性及外键检查通过，重复迁移零改动。截图位于 `.local/honors-review/`（本地验收产物，不入 Git）。
