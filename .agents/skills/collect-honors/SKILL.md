# 竞赛荣誉采集

在本仓库执行，结果放 `data/honors/`。先读 [来源与数据契约](references/sources-and-contract.md)；当前覆盖、缺口和已核对的链接见仓库 `docs/honors-plan.md`。

## 搜集与核验

- 工作坊仅收录算法竞赛。蓝桥杯只纳入 C/C++程序设计、Java软件开发、Python程序设计的大学 B 组；Web应用开发、电子、设计等非算法赛道及明确的 A/C/研究生组排除并记录原因。第十二届 Python 官方仅标“大学组”，保留当届原始称呼，不改造历史组别。用户于 2026-11-06 确认本工作坊名单均为 B 组，2025 国赛补充名单据此更正；这是组别依据，不是账号身份依据。

- 首选赛事主办方公开名单、正式公示附件；SRK 从 `algoux/srk-collection` 固定提交提取。学校官网新闻和汇总表作补充证据，标明来源类型。新闻发布时间不作比赛日期，汇总人数不能拆成未具名的个人奖项。
- 每个网络附件保留原始 URL、落地页、抓取日期、SHA-256、页码及表头。用户提供的本地附件保留原文件名、SHA-256、页码/工作表/行号及表内来源；原件下载 URL 未知时记为未知，链接只填官方入口并标明入口不是原件。下载失败、名单查无本校和未完成查找分别记录，不能都写成“无获奖”。名单存在撤销、作弊公示或更正版时核对最终版本。
- 动态网站从浏览器中公开显示的链接和网络请求发现入口。仅使用公开数据；遇到需要登录的证书、手机号或验证码入口，记录缺口，不收集身份证、手机等无关字段。
- SRK 先在仓库外检出指定提交，并安装该检出的依赖；使用 `node tools/honors/collect-srk.cjs /path/to/srk-collection data/honors`。脚本用上游 `convertToStaticRanklist` 读取 `rankValues` 与 `series.segments`，不自行套固定获奖比例。缺姓名、非正式参赛、无奖项的条目仅留候选；教练不作队员。
- 同一实体赛事可能同时在邀请赛、省赛目录出现。核对日期、队伍 ID、队员、奖项及分榜，再维护 `tools/honors/srk-event-aliases.json`；不同奖项或不同场次不能合并。保留候选和重复来源的审计信息。
- PDF 先提取文本，带着赛道和奖项章节定位本校行，再看对应页面核实列对齐；不能只根据序号猜奖牌。扫描件需要 OCR 后视觉复核。日期必须另查同届、同赛段的官方通知或院校官方通知，并记录来源、页码及 SHA-256；先查变更/延期通知，不能停在获奖压缩包年份。仍只能核实月份/年份时保留精度并列出缺口，不能补造某天。2021–2023 国赛已核实日期见 `data/honors/lanqiao-date-sources.json`。

## 人员与计入口径

原始姓名只存获奖名单中的写法。姓名、曾用名、学校一致均不能替代身份确认；审核页可以按当前姓名和用户层面登记的曾用名提出初步匹配，但不自动保存关联或公开计入；采集时不把公开姓名绑定站内账号，不把跨多届的同名记录聚成同一人。默认不从最早获奖年反推入学年。

获奖关联只指向站内用户，不再创建独立荣誉身份。曾用名和在校区间在用户层面维护（成员管理或荣誉管理的“用户资料”）。默认入学日期为用户入学年 9 月 1 日，默认离校日期为入学日期加四个日历年，两者均可在后台覆盖。计入区间为 `[入学日, 离校日)`；只有月份/年份的比赛必须整个月/全年落在区间内，跨边界则待核对。

原始名单姓名和来源始终保留。已核实且比赛已结束的记录在荣誉殿堂展示全部名单姓名，包括尚未关联站内用户的姓名；明确未来日期的记录不提前显示。未关联姓名不自动创建账号或合并身份。已关联用户只有在比赛日期完整落入其在校区间时才计入公开结果，并按用户 ID 显示在个人历史。审核页遇到多位在校时间吻合的同名用户时必须由管理员选择；只有唯一符合时间的姓名/曾用名候选才会初步预选，保存审核前不绑定。日期未核实的关联候选也不预选。用户改名后，已确认奖项仍按用户 ID 归属。

曾用名用于把不同姓名下的奖项归到同一个用户；不直接 SQL 合并登录用户，不从获奖姓名自动创建账号。旧独立身份表只作迁移留档，已明确关联用户的记录迁到用户 ID，旧的身份合并预检接口已移除。

## 交付与导入

生成 `{ "records": [...] }` 的 JSON，遵循参考中的契约。按稳定 `source_key` 去重、同一赛事共用规范化 `event.key`，重跑不改写已审核的记录。未知信息单列缺口，不塞占位获奖者。

对于用户提供的 2025–2026 蓝桥杯/天梯赛名单，使用 `python tools/honors/collect-provided-2025-2026.py /path/to/source-files data/honors` 重新提取。原文件不复制进仓库；以 manifest 的文件名与 SHA-256 固定证据。脚本只读取蓝桥工作簿“全部”总表，避免重复导入其余分表；个人奖逐人一条，团队奖一队一条，队员名单必须与同届官方队伍详情一致。若附件年份、届次、比赛日或奖项数量与官方来源冲突，逐项列出并先保留待核实，不猜测修正。

先运行后端 `ImportInput` 校验，检查关键数量及来源；新增/调整采集脚本要用真实小样运行。将新增、重复、失败、待核实分别写到采集报告，注明覆盖年份，不能宣称“历届完整”。后台 `/admin/honors` 先预览再追加；所有导入项初始待核实。审核通过后名单可进入 `/honors`；仅已关联且符合在校时间的成员显示到个人页。不直接写生产数据库。

导入成功后分别核对后台数量和公开接口数量。待核实导入不会自动公开；用户明确要求名单上线时，在其授权范围内完成奖项审核并检查公开页，身份关联仍单独处理。报告须写清“已导入待核实”或“已审核公开”。
